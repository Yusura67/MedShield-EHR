## วัตถุประสงค์และภาพรวมโครงการ

**MedShield-EHR** คือโครงการพัฒนา **ระบบต้นแบบเพื่อการศึกษา (Educational Reference Implementation / Proof-of-Concept)** โดยมีเป้าหมายเพื่อศึกษาและทดลองนำ **มาตรฐานสากลด้านความมั่นคงปลอดภัยไซเบอร์ (Cybersecurity International Standards)** มาประยุกต์ใช้กับการพัฒนาเว็บแอปพลิเคชันจริง เพื่อเป็นแนวทางในการเรียนรู้และสร้างความตระหนักรู้ด้านความปลอดภัย

### จุดประสงค์หลักของโครงการ:
1. **เพื่อการศึกษาเชิงปฏิบัติ:** ศึกษาการแปลงข้อกำหนดเชิงทฤษฎีของมาตรฐานสากล (ISO 27799, OWASP ASVS และ HL7 FHIR) ให้ออกมาเป็นโครงสร้างฐานข้อมูล, สถาปัตยกรรมระบบ และซอร์สโค้ดจริง
2. **สร้างความตระหนักรู้ด้านความปลอดภัย:** แสดงให้เห็นถึงความจำเป็นของแนวคิด **Security-by-Design** ในระบบสารสนเทศสุขภาพ ซึ่งข้อมูลคนไข้ (ePHI) จัดเป็นข้อมูลส่วนบุคคลที่มีความอ่อนไหวสูง ตามกฏหมาย PDPA/GDPR
3. **เป็นกรณีศึกษาตัวอย่าง:** เพื่อเป็นแนวทางในการป้องกันช่องโหว่ เช่น OWASP Top 10, IDOR/BOLA, และ Credential Stuffing)ผ่านกลไกการเข้ารหัสข้อมูล, การควบคุมสิทธิ์ที่เข้มงวด และระบบบันทึกรอยเท้าที่ไม่สามารถแก้ไขได้

> **หมายเหตุและข้อจำกัดความรับผิดชอบ:** โครงการนี้จัดทำขึ้นเพื่อการศึกษา วิจัย และพัฒนาทักษะทางวิศวกรรมความปลอดภัยเท่านั้น ไม่ได้มีวัตถุประสงค์เพื่อนำไปใช้งานในเชิงพาณิชย์หรือใช้ในสถานพยาบาลจริง

## มาตรฐานสากลที่นำมาศึกษาและประยุกต์ใช้

| มาตรฐานสากล | โดเมนที่ดูแล | การนำมาประยุกต์ใช้จริงในโครงการนี้ |
| :--- | :--- | :--- |
| **ISO 27799 / ISO 27001** | ความมั่นคงปลอดภัยข้อมูลสุขภาพ และระบบ ISMS | ศึกษาการควบคุมสิทธิ์ตามบทบาท (RBAC), การแบ่งแยกหน้าที่ (Separation of Duties), ระบบบันทึกรอยเท้า (Tamper-Evident Audit Log) และระบบขอเข้าถึงข้อมูลฉุกเฉิน (Break-Glass Protocol) |
| **OWASP ASVS v4.0 (Level 2)** | มาตรฐานความปลอดภัยระดับโค้ดเว็บ | ศึกษาการเข้ารหัสข้อมูลอ่อนไหวระดับฟิลด์ (AES-256-GCM), การตรวจกรองข้อมูลนำเข้าอย่างเข้มงวด, กลไกป้องกัน BOLA/IDOR และการตั้งค่า Security Headers |
| **HL7 FHIR (Release 4)** | มาตรฐานการเชื่อมโยงข้อมูลสุขภาพสากล | ศึกษาการจัดโครงสร้างข้อมูล JSON ตามมาตรฐานเวชระเบียนสากล (`Patient`, `Observation`, `Condition`) และการควบคุม Scope ของ API ทางการแพทย์ |
| **NIST SP 800-63B** | มาตรฐานการยืนยันตัวตนดิจิทัล | ศึกษาการแฮชรหัสผ่านอย่างปลอดภัย (Argon2id/Bcrypt), ระบบล็อกบัญชีอัตโนมัติป้องกัน Brute-Force (`failed_login_attempts`, `locked_until`) |

## 🛡️ ฟีเจอร์ด้านความปลอดภัยที่พัฒนาขึ้นเพื่อการเรียนรู้

### 1. ระบบจำลองการเข้าถึงข้อมูลฉุกเฉิน "Break-Glass Protocol" (ISO 27799)
ศึกษาแนวคิดการเข้าถึงข้อมูลในภาวะวิกฤต เมื่อแพทย์เวรต้องดูข้อมูลคนไข้ฉุกเฉินนอกความดูแล:
* มีขั้นตอนบังคับระบุเหตุผลทางการแพทย์ก่อนเปิดสิทธิ์
* ระบบส่งสัญญาณเตือน (Security Alert) ไปยัง Auditor ทันที
* มีการบันทึก Log ถาวรเพื่อจำลองการตรวจสอบย้อนหลัง

### 2. การเข้ารหัสข้อมูลอ่อนไหวระดับฟิลด์ (Field-Level Encryption at Rest - OWASP ASVS V6)
ทดลองใช้การเข้ารหัส **AES-256-GCM** กับข้อมูลที่มีความอ่อนไหวสูง เช่น เลขประจำตัวประชาชน และผลการวินิจฉัยโรค เพื่อศึกษาการจัดการกุญแจเข้ารหัส (KMS) แยกจากฐานข้อมูล

### 3. ระบบป้องกันการสุ่มเดารหัสผ่าน (Brute-Force & Credential Stuffing Defense - NIST 800-63B)
นำข้อกำหนดของ NIST มาแปลงเป็นคอลัมน์ฐานข้อมูลจริง: มีการนับจำนวนครั้งที่พิมพ์ผิด (`failed_login_attempts`) และล็อกบัญชีชั่วคราว (`locked_until`) เมื่อผิดเกิน 5 ครั้ง

### 4. บันทึกรอยเท้าที่ไม่สามารถปลอมแปลงได้ (Tamper-Evident Audit Trail - HL7 FHIR AuditEvent)
ศึกษาการเก็บ Log ตามโครงสร้าง `AuditEvent` พร้อมบันทึก Cryptographic Hash เพื่อป้องกันการแอบแก้ไขหรือลบลบรอยเท้าในระบบ
